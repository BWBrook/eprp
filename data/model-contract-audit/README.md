## Connectivity diagnostic

Run from the repository root:

```
python3 data/model-contract-audit/connectivity_probe.py
```

The standard-library script translates the padding/cropping/relabeling/counting
operations in deposited `Simulation.m:71–94`. It explicitly assumes MATLAB-like
column-major component ordering and eight-neighbour connectivity. A separate
reference implementation wraps longitude rows and counts components directly.
No upstream MATLAB code or climate fields are executed.

| Tiny grid | Deposited-operation maximum label | Actual surviving labels | Longitude-periodic reference |
| --- | --- | --- | --- |
| Same-latitude cells across longitude seam | 2 | 2 | 1 |
| Opposite latitude endpoints plus an interior island | 2 | 2 | 3 |
| One latitude-edge cell plus an interior island | 3 | 2 | 2 |

All three deterministic checks pass; [connectivity_results.tsv](connectivity_results.tsv)
is regenerated by the script. This demonstrates why wrapping the wrong axis and
counting a maximum label after cropping/relabeling can fail. It does **not**
quantify the impact on published outputs. Real occupancy, thresholding and the
actual runtime determine whether these cases are active. The source remains
unchanged; reproducing its numerical results would be a separate task.
