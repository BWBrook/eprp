## Answers to Claude's five questions

### 1. Keep the published-products paragraph; distinguish grouping from coding

R5 is useful. A reader needs to recognize discrepancies in deposited tables,
printed calculations and archived scores, and those belong together as
published products. Narrative grouping can differ from the dependency codes
in Table 1.

Change the ordering check at lines 113–115: it currently says that
Implementations splits into packages and published products. The spreadsheet
comparisons establish data discrepancies; the INDITEK scoring mismatch has an
unresolved cause. Calling all these implementation defects assigns more than
the checks establish. Present the Results as groups of resources and published
products, with formal primary/secondary dependency codes in Table 1. Preserve
the four-kind framework without forcing every paragraph into one exclusive box.

### 2. Keep D2 and D3 only if each explains a different decision

As written, both largely restate Results. They can earn their place by
explaining the different checks and responses:

- **D2:** with a specified source or known answer, a direct comparison can
  establish a transformation or calculation discrepancy. Explain why recording
  versions and intermediate products allows that check before a biological
  model is fitted. Do not call every published-number discrepancy an
  implementation defect; INDITEK's cause is unresolved.
- **D3:** model sensitivity and interval interpretation require different
  judgments. State the chosen model/cohort and the variation among alternatives;
  identify the uncertainty process the interval propagates. These findings
  affect how a result is interpreted, rather than supplying one universal
  corrected value. Replace “in any latitudinal analysis” with the sensitivity
  demonstrated for the tested models and points, or the analyses where those
  reconstruction choices matter.

Two short paragraphs with these distinct purposes are preferable to repeating
the observed differences. If that synthesis is not added, merge them. This is
an editorial recommendation, not a new scientific result.

### 3. Ground I4 in this program; use AI literature for context

I4's “can now” generalizes beyond the demonstrated program. More importantly,
“each step that others can rerun” promises a reproduction package that has not
been cold-tested and still depends on locally held inputs. A remote citation
cannot make our own package complete.

Use an affirmative description of this study's agent-assisted checks and
recorded evidence, commands and input hashes. External agent-research papers
can establish relevant precedents and explain the design choice; the receipts
establish what these agents did here. References should report the actual
task, human involvement and verification in each candidate paper, and decline
to support a broader capability claim when the evidence does not match it.
Do not require three citations merely to populate I4.

The plain-results rule stands. Naming the program and the records supplied
defines the demonstrated object; generality and cold-build limits remain in D6.
